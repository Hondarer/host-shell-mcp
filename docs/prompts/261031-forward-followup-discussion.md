## 調査結果

### BL-004 TestJobStdin の原因

job_start は初期入力を別の goroutine で書き込みます。直後の job_write (`close: true`) が先に `stdinMu` を取得すると、`second` を書き込んで stdin を閉じます。その後に初期入力の goroutine が `ErrStdinClosed` で終わるため、`first` が失われます。CI の失敗 (出力が `second\n` だけ) と一致します。テストの不安定さではなく、job_start と job_write の順序の不具合です。

```go
// internal/jobs/jobs.go (現状)
if opt.Stdin != "" && j.stdin != nil {
    go j.write(opt.Stdin)
}
```

### BL-004 TestPTYScreen の状況

macOS の runner で、`top` の画面が 20 秒間空のままになる場合があります (成功時は約 6 秒)。本件以前の main の CI でも同じ失敗があり、変更と無関係に起きています。`top` が描画しない原因は、runner 上では特定できていません。Linux と Windows では起きていません。
