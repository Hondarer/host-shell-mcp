## BL-001 Windows で、SOCKS4 の拒否の応答がクライアントに届かない場合がある

### 概要と問題点

- **現状の事象**: PR #6 の CI (run 41313691879 の 1 回目、コミット 9d00858。文書の移動だけのコミット) で、windows-latest の `internal/forward` の `TestSOCKS` が失敗しました。メッセージは `forward_test.go:352: SOCKS4 reply [0 0 0 0 0 0 0 0] read tcp ...: wsarecv: An existing connection was forcibly closed by the remote host.` です。作業環境の Windows で、Windows 向けに作ったテストを繰り返し実行すると、約 1,300 回中 1 回再現しました (main のコードでも同じ処理です)。
- **原因の見立て**: bridge の SOCKS の処理 (`internal/forward/socks.go` の `Manager.socks`) は、SOCKS4 の要求 (テストでは 9 バイト) のうち先頭の 2 バイトだけを読み、拒否の応答 (8 バイト) を書いて接続を閉じます。Windows は、受信して読んでいないデータが残った接続を閉じると、FIN ではなく RST を送ります。RST が先に届くと、クライアント側で未読の応答が捨てられ、読み取りが接続のリセットで失敗します。
- **本来あるべき姿**: SOCKS4 のクライアントが、OS にかかわらず拒否の応答 (`0x5b`) を受け取れること。テストが安定して成功すること。

### 経緯と見送り理由

- **摘出契機**: 本案件の CI の実行中に発生。BL-002 の対処 (CI の絞り込みの見直し) により、失敗の理由がログに残ったため、原因を推定できました。
- **今回の見送り理由**: 本案件の範囲 (接続先の `Target` の後片付け、CI の絞り込み、code-server のセッション用ソケット) の外であるため。失敗したジョブの再実行で成功することを確認しています。

### 影響範囲とリスク

- **影響対象**: bridge の SOCKS の転送 (`forward_open` の SOCKS、`--forward-socks`)、Windows の bridge。同じ形の処理 (要求を読み切らずに応答して閉じる) は、SOCKS5 の未対応の要求などにもある可能性があります。
- **放置した場合のリスク**: Windows の bridge で、SOCKS4 のクライアントが拒否の理由を受け取れず、接続のリセットとして扱う場合があります (動作上の実害は小さい)。関係のない変更の PR で CI が失敗し、再実行が必要になります。

### 推奨される対応策

- **恒久対応案**: 応答を書いた後、閉じる前に書き込み側を閉じ (`CloseWrite`)、残りの受信データを短い期限付きで読み捨ててから閉じる (いわゆる lingering close) 処理を、拒否の応答を返して閉じるすべての経路に共通で入れます。テストは、Windows で繰り返し実行して確かめます。
- **参考情報**: `internal/forward/socks.go` の `Manager.socks`、`internal/forward/forward_test.go` の `TestSOCKS` (352 行目付近)、CI run 41313691879。

### 経緯と対処

- **状態**: 解消 (2026-11-01、261101-socks-linger-close)
- **原因の確認**: クライアントが応答を読む前に 100 ミリ秒待つと、作業環境の Windows で、SOCKS4 の要求と、SOCKS5 の未対応のアドレス種別の要求の両方が、毎回接続のリセットで失敗しました (Linux では成功)。上記の見立て (読み残しのある接続を閉じると RST になり、Windows が未読の応答を捨てる) を確かめました。
- **対処**: `internal/forward/socks.go` に `lingerClose` を加え、`Manager.socks` で応答を書いて閉じる 8 つの経路すべてで使うようにしました。書き込み側を閉じ、残りの受信を最大 1 秒、64 KiB まで読み捨ててから閉じます。テスト `TestSOCKSRejectReplyDelivered` (待ってから応答を読む。修正前のコードは Windows で失敗) と `TestLingerClose` (期限と量の上限) を加えました。作業環境の Windows で、`TestSOCKS` と `TestSOCKSRejectReplyDelivered` を各 300 回繰り返して失敗は 0 回でした。
