### Q-021 sudo_run のパスワードの渡し方

**Status**

解決済み

**Question**

`sudo_run` の `password` を、sudo にどの方法で渡しますか。

**Context**

- **経緯と背景**: [Q-011](#q-011-sudo_run-のパスワード) で `password` の引数を加えることになりました。sudo にパスワードを渡す方法は 2 つあります。
- **`sudo -S` (標準入力)**: パスワードを標準入力の 1 行目として渡します。パスワードが不要な場合 (NOPASSWD の規則、認証の記録が残っている場合) は sudo がその行を読まないため、**パスワードがそのままコマンドの標準入力に流れます** (例: `sudo -S cat` なら、パスワードが出力に出ます)。避けるには、先に `sudo -n true` でパスワードが要るかを調べてから、要る場合だけ渡します。また、`stdin` の引数と同じ通り道を使います。
- **`sudo -A` (askpass)**: sudo が、パスワードを尋ねるときだけ、環境変数 `SUDO_ASKPASS` のプログラムを起動して、その出力をパスワードとして使います。host-shell 自身の実行ファイルを、パスワードを返すだけの補助として使えます (パスワードは、環境変数ではなく、host-shell から受け継いだパイプで受け渡します)。パスワードが不要なら何も起きず、標準入力とも混ざりません。

```text
案 A (askpass):  SUDO_ASKPASS=<host-shell> sudo -A -- sh -c '<command>'
                 sudo がパスワードを尋ねるときだけ、<host-shell> の補助がパイプからパスワードを返す
案 B (-S):       sudo -n true が失敗したら、sudo -S -p '' -- sh -c '<command>' に、
                 「パスワード + 改行 + stdin の内容」を標準入力として渡す
```

**Answer**

選択方式: 単一選択

- [x] A: (推奨) `sudo -A` (askpass) で、host-shell 自身を補助として使う。
- [ ] B: `sudo -S` で、先に `sudo -n true` でパスワードが要るかを調べてから渡す。
- [ ] C: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

回答者: Tetsuo Honda (Git ユーザー名)  
回答日時: 2026-10-31 03:19:27 JST (検討用 Markdown の保存時刻)

### Q-039 askpass へのパスワードの受け渡しの通り道

**Status**

解決済み

**Question**

`sudo -A` の補助 (askpass) として動く host-shell へ、パスワードをどの通り道で渡しますか。

**Context**

- **経緯と背景**: [Q-021](#q-021-sudo_run-のパスワードの渡し方) で、`sudo -A` を使い、パスワードは「環境変数ではなく、host-shell から受け継いだパイプで受け渡す」ことにしました。最終仕様の作成のために sudo のソース コード (`src/tgetpass.c` の `sudo_askpass`) を確かめたところ、sudo は askpass のプログラムを起動する前に、標準入力、標準出力、標準エラー以外のファイル記述子をすべて閉じていました (`closefrom(STDERR_FILENO + 1)`)。このため、**受け継いだパイプは askpass に届かず、合意した方式は実現できません**。
- 標準入力は askpass に渡りますが、コマンドの標準入力と同じものなので、パスワードが不要な場合にコマンドへ流れる問題 ([Q-021](#q-021-sudo_run-のパスワードの渡し方) の `sudo -S` と同じ) が起きます。
- askpass は、sudo を起動した利用者と同じ権限で動き、環境変数はそのまま受け継ぎます。

各案の振る舞い:

```text
案 A (推奨): 名前付きパイプ (FIFO)
  - 呼び出しごとに、権限 700 の一時ディレクトリを作り、その中に名前付きパイプを作る
  - 環境変数には名前付きパイプのパスだけを入れる (パスワードは入れない)
  - host-shell がパイプにパスワードを書き、askpass がそれを読んで sudo に返す
  - sudo がパスワードを尋ねなければ、だれも読まず、コマンドの終了後にディレクトリごと消す
  - 権限 700 のため、ほかの利用者はパイプを開けない

案 B: Unix ドメイン ソケット
  - 案 A と同じ一時ディレクトリにソケットを作り、askpass が接続してパスワードを受け取る
  - 接続してきた相手の利用者 ID を OS から確かめてから渡せる
  - 案 A より処理が多い

案 C: 環境変数
  - パスワードを環境変数に入れ、askpass がそれを出力する
  - sudo の動いている間、同じ利用者のほかのプロセスから /proc/<pid>/environ で読める
  - sudo の設定で環境変数を引き継ぐ場合 (env_reset を無効にしている、-E など) は、コマンドにもパスワードが渡る
```

**Answer**

選択方式: 単一選択

- [x] A: (推奨) 権限 700 の一時ディレクトリの名前付きパイプで渡す。
- [ ] B: 権限 700 の一時ディレクトリの Unix ドメイン ソケットで渡し、相手の利用者 ID を確かめる。
- [ ] C: 環境変数で渡す。
- [ ] D: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

回答者: Tetsuo Honda (Git ユーザー名)  
回答日時: 2026-10-31 03:29:58 JST (検討用 Markdown の保存時刻)

**Recommendation**

推奨: A  
理由: 合意した「パイプで受け渡し、環境変数にはパスワードを入れない」に最も近く、処理も単純です。ほかの利用者からの読み取りは、ディレクトリの権限で防げます。B は相手を確かめられますが、同じ利用者のプロセスであることは A でも権限で保たれるため、追加の効果は小さいです。
